## Cursor Cloud specific instructions

This checkout is the OhhO Quest VR client only (Unity project at the repo root). There is no web server, ROS workspace, or `./launch_vr_teleop.sh` here, so nothing needs to be started before editing.

- The Editor is pinned in `ProjectSettings/ProjectVersion.txt` to **6000.5.2f1** (changeset `eb73d3b415a1`). The Linux editor on this machine is `/opt/unity/6000.5.2f1/Editor/Unity`, also on `PATH` as `unity`. Unity Hub 3.21.3 is installed as `unityhub`. Do not run `unityhub --version` in a headless shell; that process does not exit. The only enabled build scene is `Assets/scene1.unity`.
- The Editor will not open the project until a Unity license is activated. Batchmode otherwise stops with `No valid Unity Editor license found` (missing entitlement `com.unity.editor.headless`). Sign in through Unity Hub for a Personal license; the entitlement file is `~/.config/unity3d/Unity/licenses/UnityEntitlementLicense.xml`. A paid seat can be activated with `unity -batchmode -quit -nographics -serial <serial> -username <email> -password <password>`. Hub is already signed in on this machine.
- There is no C# linter. `.github/workflows/readme-checks.yml` checks that the public docs do not point at missing files or the old Unity 2023 pin. It does not run the Unity Test Runner. Edit-mode tests are the NUnit fixtures in `Assets/Scripts/Editor/Tests/`. After a license is active, import once, then run the project fixtures with:
  `unity -batchmode -nographics -projectPath /workspace -runTests -testPlatform editmode -testFilter OmniBot.VR.Tests -testResults /tmp/unity-editmode.xml -logFile /tmp/unity-editmode.log`
  The first open resolves packages from `Packages/manifest.json` (Unity registry, OpenUPM, the Meta registry, and the NativeWebSocket git URL). Meta XR Core, Interaction, and `com.coplaydev.unity-mcp` are already vendored under `Packages/`.
- `RuntimeOptimizerPlugin.cs` in the vendored Meta package must keep its `#define` directives above any `using` statements. Unity 6000.5 reports CS1032 otherwise. `watcher.ps1` recopies that package from the Windows PackageCache and would drop the fix.
- This VM has no GPU and no Quest headset, so Play Mode, Meta XR Simulator, and an APK deploy cannot be exercised here. Unity's published Linux "Android Build Support" URL is a macOS `.pkg`, and Hub refuses to add modules to an editor that was unpacked outside Hub. A compile-only stub, `UnityEditor.Android.Extensions.dll` (`AndroidExternalToolsSettings.sdkRootPath`), is at `/opt/unity/6000.5.2f1/Editor/Data/PlaybackEngines/AndroidPlayer/` so the Meta Runtime Optimizer editor assembly can compile. It does not build Quest APKs. The editor install does include the Linux standalone player at `Editor/Data/PlaybackEngines/LinuxStandaloneSupport`.
- `CalibrationManager` (PlayerPrefs) and `HandIK6DofScheme.Configure` (`new GameObject`) call native Editor APIs. Those tests need the Unity Test Runner; a plain `dotnet` host cannot execute them.
